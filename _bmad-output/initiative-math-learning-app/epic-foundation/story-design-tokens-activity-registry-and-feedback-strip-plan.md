## Intent

**Problem:** The demo page is unstyled and judges an answer the moment the point is dropped. The frontend still hand-writes the number-line payload type (AD-7). Activities are hard-wired in `App.tsx`, not looked up by `kind` (AD-6).

**Approach:**
- **Styling:** add the Orchid Pop tokens from DESIGN.md as CSS variables, and style the page with them.
- **Content types:** generate TypeScript types from `content/schemas/` during the build, and use them instead of the hand-written payload type.
- **Registry:** put the number line behind a React activity registry keyed by `kind`.
- **Checking:** add a Check button that stays disabled until there is an answer. Add a feedback strip under the activity, green for correct and amber for a nudge, which receives focus and stays until her next action.

## Boundaries & Constraints

**Always:**
- **Colours and shapes:** CSS values come only from the token variables, transcribed from DESIGN.md's frontmatter (colors, typography, rounded, spacing, card shadow). Light mode only. No red anywhere.
- **Content types:**
  - Generated by `json-schema-to-typescript` 16.0.0 into `frontend/src/content-types/`, which is git-ignored like `src/api/schema.d.ts`.
  - The generation runs in the same `pre*` hooks as `gen:api`, so a schema change reaches `tsc` in one `./mvnw verify`.
  - No hand-written payload type remains.
- **Registry:**
  - `Record<ActivityKind, ActivityEntry>`, where `ActivityKind` is the generated `kind` union. A schema kind with no entry fails `tsc`.
  - An unknown kind at runtime shows a friendly message, never a crash.
- **Answers:** comparison stays in the kind's pure helper (AD-3: no math evaluation). The Check button and the strip are shared and kind-agnostic.
- **Messages:** "You did it!" on green, and "Not quite — have another look." on amber (EXPERIENCE.md Voice).
- **Accessibility:** the button is at least 44px tall. After Check, focus moves to the strip, which has `role="status"`.

**Never:**
- No keyboard or touch drag, dnd-kit or TypeScript fixture runner (entry 7).
- No "I'm stuck" button, nudge or hint text from content, tries, sound, Lumi or session progress (epic 2 onward).
- No backend change.
- No dark mode.

## Design Notes

**Respond, then Check.** A drop now only *records* a response. Judging happens on Check, so the strip can "stay until her next action" (EXPERIENCE.md) and focus can move to it. Grabbing the point again counts as the next action and clears the verdict.

**Registry shape.**

```ts
type ActivityKind = Concept['items'][number]['kind']          // generated union
export const registry: Record<ActivityKind, ActivityEntry> = { 'number-line': numberLineEntry }
```
